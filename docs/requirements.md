# 要件定義書

## 1. 文書情報

| 項目 | 内容 |
|------|------|
| 製品名 | card-csv-analyzer（仮） |
| 対象バージョン | 明細DB蓄積版 |
| 利用者 | 本人のみ |
| 目的 | 複数カード会社の利用明細CSVをマージし、分類付きで分析する |

---

## 2. 背景・課題

カード会社ごとに利用明細CSVの形式が異なるため、そのままでは横断分析が難しい。

主な差異:

- 文字コード（SJIS / UTF-8 BOMあり など）
- ヘッダー名
- ヘッダー開始行
- データ末尾の不要行
- 日付書式（`YYYY/MM/DD`、`YYYY年MM月DD日` など）
- 金額書式（カンマ有無など）
- 利用店名の表記ゆれ（半角カタカナ、英語表記など）

また、マージ結果を都度CSVファイルとして残すだけでは、データの蓄積・再分類・継続分析がしづらい。

---

## 3. ゴール

1. 複数の伝票CSVから、利用年月日・利用店名・利用金額を抽出してマージする
2. 店名辞書により分析用店名と分類（固定費／変動費／臨時費）を付与する
3. マージ結果をSQLiteに蓄積し、同一明細は重複登録しない
4. 蓄積明細を明細タブで閲覧・分類編集し、CSVバックアップ／リストアできる
5. 蓄積明細を対象に分類比率の円グラフと分類集計CSVを出力する
6. プロファイル・店名辞書・明細はSQLiteに保持し、Tkinter上で編集する

---

## 4. 機能要件

### 4.1 プロファイル管理

| ID | 要件 |
|----|------|
| R-P01 | カード会社ごとの読込条件をプロファイルとして登録・編集・複製・無効化・削除できる |
| R-P02 | プロファイルは設定画面からユーザーが登録する（初期データは空） |
| R-P03 | 文字コード・日付書式などはよく使う候補から選択でき、必要なら手入力もできる |
| R-P04 | 読込はプロファイルの固定値を用い、読込後にヘッダー検証を行う |
| R-P05 | テスト読込により、サンプルCSVのプレビューができる |

プロファイルに含める主な項目:

- プロファイル名
- カード会社名
- 文字コード
- ヘッダー開始行
- 末尾不要行数
- 日付列名／店名列名／金額列名
- 日付書式
- 金額書式（カンマ、通貨記号、マイナス表記など）
- 有効／無効

### 4.2 伝票マージ

| ID | 要件 |
|----|------|
| R-M01 | 複数のCSVファイルを選択できる |
| R-M02 | 各ファイルのプロファイルはユーザーが手動選択する |
| R-M03 | マージ前に検証できる（文字コード、ヘッダー、日付／金額変換、明細有無） |
| R-M04 | 日付・金額を変換できない行は除外する |
| R-M05 | 検証エラーがある場合はマージ全体を中止する |
| R-M06 | 除外行のみの場合は有効明細をDBへ保存し、完了後に案内する |
| R-M07 | マージ成功時、明細はSQLiteへ保存する（CSV自動出力はしない） |
| R-M08 | 同一明細はスキップする（重複判定キーは下記） |
| R-M09 | 完了時に登録件数・スキップ件数を案内できる |
| R-M10 | 保存する利用金額は整数（円）とする |
| R-M11 | 保存する利用年月日は `YYYY/MM/DD` とする |
| R-M12 | マイナス金額（返金・取消）は取り込む |

重複判定キー（全項目一致で同一明細）:

1. カード会社
2. 利用年月日
3. 利用店名
4. 利用金額
5. 取込元ファイル名
6. 取込行番号

マージ結果として保持する列:

1. 利用年月日
2. 利用店名（原文）
3. 正規化店名
4. 分類
5. 利用金額
6. カード会社
7. 取込元ファイル名
8. 取込行番号
9. 分類手動（手修正フラグ。マージ直後は未手修正）

### 4.3 明細（閲覧・分類編集・バックアップ／リストア）

明細の閲覧・分類の個別編集・CSVバックアップ／リストアは「明細」タブで行う。

| ID | 要件 |
|----|------|
| R-T01 | 蓄積済み明細を一覧表示できる |
| R-T02 | 年月・カード会社・分類などで明細を絞り込める |
| R-T03 | 一覧に利用年月日・利用店名・正規化店名・分類・利用金額・カード会社・分類手動などを表示できる |
| R-E01 | 蓄積済み明細の分類を個別に変更できる |
| R-E02 | 分類の選択肢は「固定費／変動費／臨時費／未分類」とする |
| R-E03 | 個別編集した明細は分類手動を立て、以降の辞書再適用対象外とする |
| R-E04 | 明細の削除機能は提供しない |
| R-B01 | 明細タブのボタンからCSVバックアップを実行できる |
| R-B02 | バックアップ先はファイルダイアログで任意パスを選択する |
| R-B03 | バックアップCSVはUTF-8（BOMなし）・全項目ダブルクォートとする |
| R-B04 | バックアップCSVの利用金額はカンマありの整数（円）とする |
| R-B05 | バックアップCSVには手修正フラグ（分類手動）を含める |
| R-B06 | 明細タブのボタンからCSVリストアを実行できる |
| R-B07 | リストア元はファイルダイアログで任意パスを選択する |
| R-B08 | リストアは既存明細を全消去してからCSV内容で復元する |
| R-B09 | リストアにより分類手動の状態も復元する |

バックアップ／リストアCSVの列:

1. 利用年月日
2. 利用店名
3. 正規化店名
4. 分類
5. 利用金額
6. カード会社
7. 取込元ファイル名
8. 取込行番号
9. 分類手動

### 4.4 店名辞書

| ID | 要件 |
|----|------|
| R-D01 | 店名の分析用名称と既定分類を辞書登録できる |
| R-D02 | 分類は「固定費／変動費／臨時費／未分類」から選択する |
| R-D03 | 照合キーはアプリが自動生成する（NFKC等）。基本は手編集しない |
| R-D04 | 利用店名（原文）は変更せず保持する |
| R-D05 | 辞書未登録の店は、正規化店名＝原文、分類＝未分類とする |
| R-D06 | Tkinter上で追加・編集・削除・検索できる |
| R-D07 | 辞書内容を既存明細へ再適用できる |
| R-D08 | 再適用時、分類手動が立っている明細は正規化店名・分類を変更しない |

### 4.5 未登録店名

| ID | 要件 |
|----|------|
| R-U01 | マージ時に辞書未ヒットの店名を未登録一覧へ記録する |
| R-U02 | 出現回数・最終カード会社・最終ファイルなどを保持する |
| R-U03 | 画面上で分析用名称・分類を入力し、店名辞書へ登録できる |

### 4.6 分析

| ID | 要件 |
|----|------|
| R-A01 | SQLiteに蓄積した明細を対象に分析できる |
| R-A02 | 年月単位で期間を指定できる |
| R-A03 | カード会社・分類で絞り込める |
| R-A04 | 返金・取消（マイナス金額）を含めるかON/OFFできる |
| R-A05 | 固定費／変動費／臨時費／未分類の円グラフを表示できる |
| R-A06 | 分類ごとの合計金額・件数・割合を表で表示できる |
| R-A07 | 未分類の件数・金額を明示する |
| R-A08 | 集計結果を `category_summary_YYYYMMDD_HHMMSS.csv` として保存できる |
| R-A09 | 円グラフを `category_pie_YYYYMMDD_HHMMSS.png` として保存できる |
| R-A10 | 円グラフの日本語は Meiryo で表示し、文字化けしない |
| R-A11 | フィルタ後の明細をCSVとして出力できる（列はマージ結果の8列。分類手動は含めない） |

分析タブは集計・可視化に専念する。明細の閲覧・分類編集・バックアップ／リストアは明細タブで行う。

### 4.7 ログ・通知

| ID | 要件 |
|----|------|
| R-L01 | マージ実行時に `log/merge_YYYYMMDD_HHMMSS.log` を作成する（開始時刻基準） |
| R-L02 | ログに開始・除外・エラー・終了を記録する |
| R-L03 | 除外行がある場合、ポップアップは「除外行があります。詳細はログを確認してください。」のみとする |
| R-L04 | エラー時のポップアップは「エラーが発生しました。詳細はログを確認してください。」とする |
| R-L05 | 除外行の詳細（元ファイル名、行など）はログに出力する |
| R-L06 | 除外通知は全ファイル処理後にまとめて行う |

### 4.8 UI全般

| ID | 要件 |
|----|------|
| R-G01 | GUIは Tkinter（ttk）で実装する |
| R-G02 | 画面タブは「マージ／明細／プロファイル設定／店名辞書／未登録店名／分析」とする |
| R-G03 | GUI起動は `gui.py` から行う |
| R-G04 | 長時間処理中も画面を固めない（別スレッド等） |
| R-G05 | 起動時、メインウィンドウは画面の上下左右中央に配置する |

---

## 5. 非機能要件

| ID | 要件 |
|----|------|
| R-N01 | 依存パッケージは `requirements.txt` で管理する |
| R-N02 | DBは `data/app.db` に置く（プロファイル・店名辞書・未登録店名・明細） |
| R-N03 | 分析結果（集計CSV・円グラフPNG）および明細バックアップCSVの既定候補は `results/` とする |
| R-N04 | ログは `log/` に保存する |
| R-N05 | DB初期データは空テーブルのみ（サンプル同梱なし） |
| R-N06 | DBファイル全体のバックアップは手動コピーとする（明細のCSVバックアップ／リストアとは別） |
| R-N07 | 金額は整数（円）のみ。小数・ポイント・手数料は対象外 |
| R-N08 | 明細単位の分類上書き（分類手動）を提供する |

---

## 6. 対象外

- 明細の削除（個別・期間・全クリアUI）
- ファイル名／ヘッダーによるプロファイル自動判定
- 店名のあいまい一致（照合キーの完全一致のみ）
- 月別推移・店別ランキングなどの追加分析
- 設定・辞書の手動JSON編集を前提とした運用
- 他利用者向けの配布・インストール一式
- 分析処理専用ログ（必要なら将来追加）
- マージ実行時の `merged_*.csv` 自動出力

---

## 7. 入出力仕様（要約）

### 入力

- カード会社の利用明細CSV（複数）
- ユーザーが登録したプロファイル
- 店名辞書
- 明細バックアップCSV（リストア時）

### 出力

| 種類 | パス例 |
|------|--------|
| DB（明細含む） | `data/app.db` |
| 明細バックアップCSV | ユーザー指定（例: `results/transactions_backup_*.csv`） |
| 分類集計CSV | `results/category_summary_YYYYMMDD_HHMMSS.csv` |
| 分析明細CSV | `results/` 配下などユーザー指定 |
| 円グラフPNG | `results/category_pie_YYYYMMDD_HHMMSS.png` |
| マージログ | `log/merge_YYYYMMDD_HHMMSS.log` |

---

## 8. 用語

| 用語 | 意味 |
|------|------|
| プロファイル | 伝票形式ごとの読込・変換条件 |
| 利用店名 | 伝票上の原文店名 |
| 正規化店名 | 辞書の分析用名称。未登録時は原文 |
| 照合キー | 辞書照合用に正規化した文字列 |
| 既定分類 | 店名辞書に紐づく分類 |
| 分類手動 | 明細単位でユーザーが分類を手修正した状態。辞書再適用の対象外 |
| 未分類 | 辞書未登録、または分類未設定 |
| 除外行 | 日付または金額を変換できず明細として採用しない行 |
| 検証エラー | ファイル単位で読込・ヘッダー検証などに失敗し、マージ中止の原因となるエラー |
| CSVバックアップ | 蓄積明細を9列CSVへ書き出す操作 |
| CSVリストア | 既存明細を全消去し、バックアップCSVから復元する操作 |
