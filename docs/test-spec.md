---

## 2. テスト方針

| 層 | 手段 | 対象 |
|----|------|------|
| ユニット | pytest | `normalize.py`（日付・金額・照合キー・分類決定） |
| 統合 | pytest + 一時DB / 一時CSV | `db.py` / `merge.py` / `analyze.py` |
| GUI・見た目・体感 | 手作業チェックリスト | タブ操作、ポップアップ文言、円グラフ日本語、画面中央、フリーズしないこと |

成功基準:

1. 自動テストが全件 PASS
2. 手動チェックリストを実施し、致命的な NG がない
3. 上記カバレッジ目標を達成する

補足: プロファイル設定画面の「テスト読込」はアプリ機能名であり、pytest のテストとは別物とする。

---

## 3. 環境・実行方法

| 項目 | 内容 |
|------|------|
| OS | Windows 10/11 |
| Python | 3.10 以降想定 |
| 依存 | `requirements.txt`（pandas, matplotlib, pytest, pytest-cov） |

```text
# 依存インストール
pip install -r requirements.txt

# テスト + カバレッジ（pyproject.toml の addopts で coverage 付き）
pytest
```

カバレッジはターミナル表示に加え、`htmlcov/index.html` にも出力される（`.gitignore` 済み）。

設定はリポジトリ直下の `pyproject.toml`（`[tool.pytest.ini_options]` / `[tool.coverage.*]`）に定義する。

## 4. 自動テストケース

### 4.1 normalize（ユニット）— `tests/test_normalize.py`

| ID | 関連要件 | 内容 | 期待結果 |
|----|----------|------|----------|
| AT-N01 | R-D03 | NFKC・前後空白・連続空白の正規化 | 半角カナ等が揃い、照合キーが安定する |

| AT-N05 | R-M04 | 変換失敗 | 空・不正日付・不正金額は `None` |

## 6. テストデータ

| 種別 | 置き場 | 説明 |
|------|--------|------|
| 自動用 CSV | `tests/fixtures/` | 最小の UTF-8 / 除外行あり（日付・金額不正・店名空） / ヘッダー不一致 など |
| 手動用 | 利用者手元の実伝票 | リポジトリには含めない（個人情報のため） |

自動テストは一時ディレクトリに DB（`data/app.db`）/ results / log を切り替えて実行し、本番の `data/app.db` や `results/` を汚さない。

## 7. 合格／不合格の判定

| 判定 | 条件 |
|------|------|
| 合格 | 自動全件 PASS、カバレッジ目標達成、手動の致命的 NG なし |
| 条件付き合格 | 軽微な手動指摘のみ（見た目・文言の微差など）。要対応を結果書に記載 |
| 不合格 | 自動 FAIL、またはマージ破損・データ損失・要件未達の手動 NG |

結果の記録は [テスト結果報告書](./test-results.md) に残す。
